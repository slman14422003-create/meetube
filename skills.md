## Decisions
- SeekThumb is the seek bar's dot picture (one file), not a per-position preview, so "stale" = view detached or file replaced, not a changed seek position
- Only commit() on the main thread was SettingsTransferActivity restore: now apply() + PrefCache.invalidate(name); the existing 600 ms delay before restartTheAppAsStored is what lets it reach disk. MobileSettingsActivity/FilePickerActivity commit() are fragment transactions, left alone
- Not converted (not in the step 3 list): MobilePlaybackActivity.cornerControls, NavLens.lowEnd (ActivityManager call per enabled() when untouched)
- No setHasFixedSize on nested wrap_content strips (stale height when a recycled row changes card type)
- No stable IDs on VideoCardAdapter/FeedStrip (duplicate videos / index ids would crash)
- Not compiled here (no network/Gradle): run :mobile:assembleStmobileDebug and unit tests first

## Not verified here
